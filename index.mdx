Go SIEM Agent is a production-ready Security Information and Event Management (SIEM) system built in Go. Paste any log line — syslog, nginx, auth.log, Windows Event — and the agent parses, classifies, maps to MITRE ATT&CK, extracts IOCs, and autonomously investigates high-severity events using a tool-calling LLM loop. Results stream live to a React dashboard over WebSocket.

## What the agent does

When a log line arrives, the SIEM agent runs a multi-step pipeline automatically:

<Steps>
  <Step title="Parse">
    Detects RFC 5424 syslog, RFC 3164 syslog, JSON, or raw text and extracts structured fields: hostname, app name, timestamp, and message body.
  </Step>
  <Step title="Classify">
    Sends the structured event to an OpenAI-compatible LLM (default: Kimchi / minimax-m3) and receives a structured JSON response with attack type, severity (P1–P5), confidence score, MITRE tactic/technique, IOCs, summary, and remediation steps.
  </Step>
  <Step title="Enrich & Store">
    Generates a vector embedding via Ollama (`nomic-embed-text`) and stores the event in Qdrant for semantic similarity search. IOCs are auto-linked to VirusTotal and AbuseIPDB.
  </Step>
  <Step title="Investigate (P1/P2 only)">
    High-severity events automatically trigger an autonomous agent loop. The LLM calls threat-intel tools — MITRE lookup, AbuseIPDB IP reputation, AlienVault OTX, and similar-event recall — then writes a full incident playbook streamed live to the dashboard.
  </Step>
</Steps>

## Tech stack

| Layer | Technology |
|---|---|
| Backend | Go 1.25, Chi router |
| LLM Provider | Kimchi (`llm.kimchi.dev`) — any OpenAI-compatible API |
| Vector DB | Qdrant (gRPC) |
| Embeddings | Ollama — `nomic-embed-text` (768-dim) |
| Database | PostgreSQL 16 |
| Metrics | Prometheus |
| Frontend | React 19, TypeScript, Vite, Tailwind CSS |

<Note>
  Any OpenAI-compatible LLM provider works. Set `KIMCHI_BASE_URL` and `SIEM_MODEL` to point at OpenAI, Groq, Mistral, or a local Ollama model.
</Note>
