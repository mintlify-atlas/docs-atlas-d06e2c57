The analytics panel visualises the last 1,000 classified events held in the backend's in-memory ring buffer. Every chart and counter polls `GET /api/analytics/summary` on a 30-second interval (with a 15-second stale-time), so the view stays fresh without manual refreshing. On desktop the panel sits in the right column of the dashboard; on mobile, switch to the **Analytics** tab in the bottom tab bar to reveal it.

## Analytics views

### Critical / High counters

Two large numerical badges at the top of the panel show the total count of P1 Critical and P2 High events across all stored data. These are derived from the `attack_type_counts` field of the summary — they sum all entries whose `severity` is `"P1"` or `"P2"` respectively.

### Attack type bar chart

A horizontal bar chart (rendered via [Recharts](https://recharts.org) `BarChart`) showing the top 10 attack types ordered by event count. Each bar is coloured using the highest severity seen for that attack type — so a "Brute Force" bucket that contains one P1 event renders in the P1 colour even if most of its events are P3.

Data source: `attack_type_counts` from `GET /api/analytics/summary`.

```json
"attack_type_counts": {
  "Brute Force":       { "count": 87, "severity": "P2" },
  "Command Injection": { "count": 12, "severity": "P1" }
}
```

### Event rate timeline

A multi-line chart covering the last **6 hours** split into **36 × 10-minute buckets**. Three overlaid line series display the P1, P2, and P3 event counts per bucket:

- P1 — solid line, P1 severity colour
- P2 — solid line, P2 severity colour
- P3 — dashed line, P3 severity colour

Data source: `timeline` array from the summary.

```json
"timeline": [
  { "time": "10:00", "counts": { "P1": 0, "P2": 3, "P3": 7 } },
  { "time": "10:10", "counts": { "P1": 1, "P2": 1, "P3": 4 } }
]
```

### MITRE tactic pie chart

A donut chart showing the distribution of MITRE ATT&CK tactics across all stored events, limited to the top 6 tactics by count. Tactics labelled `"N/A"` are excluded. Eight sequential colours cycle through the segments for visual distinction.

Data source: `mitre_tactics` from the summary.

```json
"mitre_tactics": {
  "Credential Access": 87,
  "Defense Evasion":   34,
  "Execution":         21
}
```

### MITRE ATT&CK heatmap

Below the `AnalyticsPanel`, the `MITREHeatmap` component renders a **tactic × weekday** grid — 14 MITRE tactics (in kill-chain order, Reconnaissance → Impact) against the 7 days of the week. Each cell encodes two dimensions:

- **Colour** — the highest severity of any event in that tactic/weekday bucket
- **Opacity** — event volume relative to the busiest cell (0.15 at minimum, 1.0 at maximum)

Hover over any cell for a tooltip showing the tactic name, weekday, event count, and highest severity. The heatmap is computed entirely in the browser from the current session's event list using a `useMemo` hook.

### Threat intel panel

The `ThreatIntelPanel` component surfaces enriched intelligence cards gathered by the autonomous agent during incident investigations. It scans the tool invocations of every incident for `check_abuseipdb` and `check_otx` results and renders them as cards:

<Tabs>
  <Tab title="AbuseIPDB cards">
    Shows the queried IP address, an abuse confidence score badge (green < 25 %, amber 25–74 %, red ≥ 75 %), country, ISP, and total report count.
  </Tab>
  <Tab title="AlienVault OTX cards">
    Shows the queried indicator, the number of OTX pulses that reference it, and up to six threat labels rendered as purple badges.
  </Tab>
</Tabs>

If no agent investigations have run yet, the panel displays "No external threat intel".

## Analytics API summary shape

All analytics charts are driven by a single endpoint:

```bash
GET /api/analytics/summary
```

Full response shape:

```json
{
  "total_events": 142,
  "attack_type_counts": {
    "Brute Force": { "count": 87, "severity": "P2" }
  },
  "timeline": [
    { "time": "10:00", "counts": { "P1": 0, "P2": 3, "P3": 7 } }
  ],
  "mitre_tactics": {
    "Credential Access": 87
  }
}
```

| Field | Type | Description |
|---|---|---|
| `total_events` | `number` | Total events in the ring buffer |
| `attack_type_counts` | `object` | Event count and highest severity per attack type |
| `timeline` | `array` | 36 × 10-min buckets for the last 6 hours |
| `mitre_tactics` | `object` | Event count per MITRE ATT&CK tactic |

## Data persistence

<Note>
  All analytics data is stored in the **in-memory ring buffer** (maximum 1,000 events). Restarting the Go backend clears all analytics state — charts will show empty until new events are classified. Use `make seed` to repopulate 10 sample events quickly, or re-upload `siemagent/test-logs.log` to restore a richer dataset.
</Note>

<Tip>
  On mobile, tap the **Analytics** tab in the bottom tab bar to switch from the event feed to the full analytics view — all charts, the MITRE heatmap, and the threat intel panel are available there.
</Tip>

For full endpoint documentation including request parameters and response schemas, see the [Analytics API reference](/api-reference/analytics).
