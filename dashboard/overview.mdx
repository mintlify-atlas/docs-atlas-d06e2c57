The Go SIEM Agent dashboard is a React 19 + Vite application that connects to the Go backend running on port `8080`. It gives you a live window into every classified security event — from the moment a log line is submitted, through LLM classification, MITRE ATT&CK mapping, and autonomous agent investigation. Open your browser to `http://localhost:5173` after starting both the backend and the Vite dev server to get started.

## Three-column desktop layout

On desktop screens wider than 1280 px, the dashboard renders three vertical columns side-by-side:

| Column | Contents |
|---|---|
| **Sidebar** | App branding, navigation (Events / Analytics / Docs), severity filter checkboxes with live event counts, and a "Clear all" button |
| **Event list** | Scrollable feed of classified event cards, statistics bar, and the log input / upload controls in the top header |
| **Detail / analytics panel** | Event detail panel (when a card is selected) or the analytics panel and MITRE heatmap (when no card is selected) |

## Responsive breakpoints

The layout adapts automatically at three breakpoints:

| Breakpoint | Layout |
|---|---|
| Mobile (< 768 px) | Hamburger sidebar, tab bar (Events / Analytics / Docs), bottom-sheet event detail |
| Tablet (768–1280 px) | Collapsible sidebar, full event list, detail panel as overlay |
| Desktop (> 1280 px) | Three-column: sidebar + events + detail/analytics panel |

## Main UI elements

### Log input bar

The top header contains a full-width text input. Paste any log line — syslog, nginx access log, `auth.log`, Windows Event, or raw text — and press **Enter** or click the **Classify** button. While classification is in progress the button shows a pulsing activity icon and reads "Classifying…".

### Upload button

To the left of the log input is the **Upload** button (DropZone component). Click it to select a `.log` or `.txt` file from disk, or drag and drop a file directly onto the button. The UI classifies all non-blank, non-comment lines in parallel batches of five and renders an inline progress bar (`done/total`) while work is in progress. A toast notification appears on completion summarising how many events were classified and how many were P1 Critical or P2 High.

### Severity filter

The sidebar contains a **Filter by Severity** section with five checkboxes — P1 through P5. Each checkbox shows the live count of events at that severity in the current session. Unchecking a severity hides those cards from the event feed without removing them from memory. A **Clear all** button at the bottom of the sidebar removes all events.

### Event feed

The centre column is a scrollable list of `EventCard` components, one per classified event. Each card shows:

- A left-border accent coloured by severity
- Severity badge (P1–P5) and attack type name
- Hostname and application name (when parsed from the log)
- A one-line summary of the threat
- MITRE ATT&CK tactic/technique badge
- A mini confidence bar with percentage

P1 Critical cards render with a `severity-pulse` animation to draw immediate attention. Clicking a card opens the event detail panel.

### Event detail panel

Clicking an event card opens the **detail panel** on the right (desktop) or as a bottom sheet (mobile). It contains:

- **Severity badge** and attack type heading
- **AI-generated summary** of the threat
- **Confidence bar** — blue ≥ 80 %, amber ≥ 60 %, grey below 60 %
- **MITRE ATT&CK** tactic, technique ID, and technique name with a link to `attack.mitre.org`
- **Indicators of Compromise (IOCs)** — IPs, domains, and file hashes with VirusTotal / AbuseIPDB enrichment links
- **Recommended action** — collapsible remediation steps generated by the LLM
- **Raw log** — the original log line rendered in a monospace code block
- **Log metadata** — parsed source, hostname, and application name badges
- **Similar past events** — semantic search results from Qdrant showing related events from history

### Alert ticker

When the agent investigates a P1 or P2 event it streams live progress to all connected clients. The `AlertTicker` component renders a fixed banner at the top of the viewport for each active or recently-completed incident. Each entry shows an `INCIDENT` badge with a pulsing animation, the incident ID in monospace, and a status indicator:

- 🔄 Spinning orange loader — **Investigating…**
- ✅ Green check — **Playbook ready**
- ⚠️ Red triangle — **Investigation failed**

Click any ticker entry to open the **incident overlay** showing full tool call details and the final playbook.

### Analytics panel

The right panel (or the **Analytics** tab on mobile) shows visualisations of all events classified in the current session:

- **Critical / High counters** — large numerical badges for P1 and P2 event totals
- **Attack type bar chart** — top-10 attack types, bar colour derived from the highest severity seen for each type
- **Event rate timeline** — 6-hour rolling chart with 36 × 10-minute buckets, overlaid P1/P2/P3 line series
- **MITRE tactic pie chart** — up to six top tactics as a donut chart

Below the analytics panel the **MITRE ATT&CK Heatmap** shows a tactic × weekday grid where colour encodes the highest severity and opacity encodes event volume.

<Tip>
  During development the Vite dev server proxies all `/api/*` and `/ws/*` requests to the Go backend at `http://localhost:8080`. You do not need to change any `baseURL` in the frontend code — the proxy is configured automatically in `vite.config.ts`.
</Tip>
