Every event classified by Go SIEM Agent is mapped to a MITRE ATT&CK tactic and technique as part of the standard LLM classification response. The mapping is produced by the same LLM call that assigns severity, extracts IOCs, and generates remediation — making it zero-overhead. For P1 and P2 events, a dedicated MITRE lookup agent tool then enriches the investigation further with detection guidance from a local ATT&CK subset.

## The MITREInfo struct

The tactic and technique information is embedded directly in every `ClassifiedEvent` via the `MITREInfo` struct:

```go
type MITREInfo struct {
    Tactic      string `json:"tactic"`
    TechniqueID string `json:"technique_id"`
    Technique   string `json:"technique"`
}
```

The LLM is instructed to populate these fields from the full ATT&CK taxonomy. For benign events the LLM sets all three fields to `"N/A"`. The system prompt enumerates valid tactics so the model produces consistent tactic names:

> `Initial Access, Execution, Persistence, Privilege Escalation, Defense Evasion, Credential Access, Discovery, Lateral Movement, Collection, Command and Control, Exfiltration, Impact`

## The MITRE lookup agent tool

During P1/P2 investigations, the agent has access to a `lookup_mitre` tool that resolves a technique ID against a curated local ATT&CK subset. The tool requires no API key and works fully offline, making it deterministic and fast.

```go
// MITRELookup returns local ATT&CK detail for a technique ID. No API key needed.
type MITRELookup struct{}

func (MITRELookup) Name() string        { return "lookup_mitre" }
func (MITRELookup) Description() string { return "Look up a MITRE ATT&CK technique by ID." }
func (MITRELookup) Schema() json.RawMessage {
    return json.RawMessage(`{
        "type": "object",
        "properties": {
            "technique_id": {
                "type": "string",
                "description": "e.g. T1110.001"
            }
        },
        "required": ["technique_id"]
    }`)
}
```

The tool returns a JSON object with the technique name, tactic, and a detection recommendation:

```json
{
  "technique_id": "T1110.001",
  "technique": "Brute Force: Password Guessing",
  "tactic": "Credential Access",
  "detection": "Threshold failed auth attempts per account/IP."
}
```

The local subset covers 18 techniques — exactly those that the SIEM's LLM classifier is trained to identify. If the agent queries a technique that is not in the subset, the tool returns a `note` field rather than an error, so the investigation loop continues gracefully:

```json
{
  "technique_id": "T9999",
  "note": "not in local ATT&CK subset"
}
```

## MITRE heatmap in the dashboard

The **Analytics** panel includes a MITRE ATT&CK heatmap that visualises the distribution of classified events by tactic and technique. Each cell's colour intensity represents the relative event count for that tactic/technique pair, letting operators quickly spot which parts of the kill chain are most active in their environment.

The **MITRE ATT&CK tactic pie chart** gives a high-level breakdown of events by tactic — useful for distinguishing between opportunistic reconnaissance (Discovery, Credential Access) and targeted intrusions (Lateral Movement, Exfiltration, Impact).

## Technique links in the event detail panel

When viewing an event's detail in the dashboard, the MITRE tactic and technique are displayed as badges. The technique ID (e.g. `T1110.001`) is a clickable hyperlink to the corresponding page on [attack.mitre.org](https://attack.mitre.org), giving analysts direct access to the full technique description, procedure examples, and mitigation guidance without leaving the incident context.

<Tip>
  Use the MITRE tactic distribution in the Analytics panel to build a threat landscape picture for your environment. A spike in **Credential Access** events indicates active brute-force or credential-stuffing campaigns; a growing **Exfiltration** slice warrants immediate egress-traffic review.
</Tip>
